# VoiceSorter · 声纹分拣器

把一大堆配音音频按「谁在说话」自动分类，导出后直接拿去训练音色克隆。

全本地运行，不联网、不上传、不需要显卡。

---

## 它解决什么问题

假设你有一个游戏的语音包，四万条音频，文件名全是 `Siren14Voice_12345678.aac`。
你知道里面有女主角的声音，但不知道哪条是谁。

VoiceSorter 的做法：

1. 随机抽几百条，自动聚类，让它们自己分成若干堆
2. 你听样本，给需要的堆起名（「爱花」「宁宁」「凛子」），不要的留空
3. 用这套「角色库」给全部四万条分类
4. 逐条试听，错的改判或删除；删一条会自动找出同类的可疑条目
5. 按角色分文件夹导出

参考时间（4 万条、24 线程 CPU）：声纹提取 **3.5 分钟**，聚类 **4 秒**，分类 **3 秒**，导出 **1 分钟**。

## 快速开始

### 整合包（推荐）

1. 解压 `VoiceSorter-1.1.0.zip` 到任意目录（别放 `C:\Program Files`，要管理员权限）
2. 双击 `VoiceSorter.exe`（被拦截时用 `启动.bat`）
3. 浏览器自动打开 `http://127.0.0.1:8756`（端口被占用会自动换，看黑窗口里打印的地址）
4. 按页面 ①～⑤ 走完

关掉黑色命令行窗口就退出。

**首次启动会被 Windows SmartScreen 拦一次**：点「更多信息」→「仍要运行」。程序没签名，不是病毒。

### 源码运行

```bash
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python -m voicesorter serve
```

首次运行会自动下载声纹模型（27 MB）。

## 五个步骤

### ① 选择目录

| 输入框 | 填什么 |
|---|---|
| 音频目录 | 你的音频文件夹（默认递归扫子目录） |
| 导出目录 | 分类结果放哪 |
| 项目数据目录 | 存声纹缓存和设置，建议放在音频目录下的 `voicesorter` |

每个框右边有「浏览」，点开是**程序内置的目录浏览器**，也可以直接粘路径。

**「打开已有项目」** 会列出所有做过的项目（记录存在 `%USERPROFILE%\.voicesorter\projects.json`），可以直接打开、移除记录或删除整个项目。

### ② 抽样聚类

点「开始处理」，自动完成三步：扫描 → 提取声纹 → 聚类。

- **抽样条数**：默认 500，样本越多聚类越准，但更慢
- **簇数量**：填 0 自动估计；估得不准就手动填
- **并发进程数**：打开页面时按你的 CPU 自动填好（线程数 ÷ 2，上限 12），实测 12 是最快档
- **低温模式**：并发降到 2，笔记本不烫，代价是慢 2~3 倍

跑完出现若干 `cluster 00`、`cluster 01`……每个簇下面是 20 条试听。

**给需要的簇填名字**，同一个角色的不同情绪簇填同样的名字即可，会自动合并。留空的归入「其他」，不导出。

### ③ 全量分类

用角色库给全部音频分类。每条要过三关：

```
① 和所有角色比，取最高相似度
② ≥ 阈值（默认 0.65）
③ 比第二名高 ≥ 0.03
   三关全过 → 归该角色
   否则     → 归「其他」
```

**另外两道质量过滤**（可关）：

| 过滤 | 默认 | 作用 |
|---|---|---|
| 最短时长 | 1.0 秒 | 短于这个的是语气词，对训练无用，直接剔除 |
| 过滤异常响亮 | 开 | 响度 > 0.25 的尖叫/呼喊剔除 |

被剔除的片段不会出现在校对列表，也不会导出。

### ④ 人工校对

默认按相似度**从低到高**排，最可疑的排最前。

| 按键 | 动作 | 计入校准 |
|---|---|---|
| `空格` | 播放 / 暂停 | 播放即视为**确认** |
| `1`~`9` | 改判到第 N 个角色 | 负样本 |
| `C` | 确认（不切走） | 正样本 |
| `0` | 归入「其他」 | 负样本 |
| `D` | 删除，并找出同类可疑条目 | 负样本 |
| `←` `→` | 上一条 / 下一条 | — |

**追着杀**：删一条后，系统拿它的声纹去**全部音频**里找同标签、相似度 ≥ 0.82 的，最多列 30 条，可以一次全部归入「其他」。范围是全库，不是当前加载的 60 条。

**自动校准**：用你的标记反推阈值。需要至少 3 条确认 + 3 条否定。算出来会建议一个新阈值，确认后重新分类。

> 注意：如果确认组的最低分**低于**否定组的最高分，说明两组无法分开，任何阈值都会误判——校准会返回 `separable: false`，这时只能靠人工。

### ⑤ 导出

| 格式 | 体积 | 说明 |
|---|---|---|
| WAV（原始采样率） | 总时长 × 采样率 × 2 字节 | 单声道 16-bit，供训练用 |
| 复制原文件 | 原始文件大小之和 | 不转码、秒级完成 |

**体积取决于你的素材，没有固定值。** 页面会按实际采样率估算两种格式的大小，并和磁盘可用空间对比。

导出结构：

```
导出目录\
├── 角色A\
├── 角色B\
├── 角色C\
└── manifest.csv    （角色、原文件名、相似度、与第二名差、时长、输出路径）
```

「其他」不导出。

## 角色库分享

②页的「导出角色库」会生成一个 `characters.json`（10~20 KB），里面是每个角色的声纹向量 + 名字，**不含任何音频**。

别人导入后，可以跳过聚类直接分类，但**必须先有自己的项目声纹**——角色库只是「标准答案」，还要拿自己的音频去比。

导入时会校验模型标识和向量维度，不匹配直接拒绝。

> 声纹属于生物特征，别把角色库传到公开仓库。

## 命令行

```bash
python -m voicesorter init     --project ./proj --input ./clips --output ./result
python -m voicesorter scan     --project ./proj
python -m voicesorter embed    --project ./proj --workers 8
python -m voicesorter cluster  --project ./proj --sample-size 500 --k 0
python -m voicesorter build    --project ./proj --assign 0=爱花 1=宁宁 2=凛子
python -m voicesorter classify --project ./proj --threshold 0.65 --margin 0.03
python -m voicesorter export   --project ./proj
python -m voicesorter clean    --project ./proj --others --cache
python -m voicesorter serve    --project ./proj --port 8756
```

每个阶段都会把结果落盘，中断了重跑同一条命令即可续上。

## 技术细节

| 组件 | 说明 |
|---|---|
| 声纹模型 | [3D-Speaker](https://github.com/modelscope/3D-Speaker) CAM++，192 维，中文训练 |
| 推理 | [sherpa-onnx](https://github.com/k2-fsa/sherpa-onnx)，ONNX Runtime，**纯 CPU** |
| 解码 | PyAV（自带 FFmpeg，不需要单独装） |
| 聚类 | KMeans + 余弦距离，k 由轮廓系数估计 |
| 后端 | FastAPI + uvicorn，只监听 `127.0.0.1` |

**为什么不用 GPU**：sherpa-onnx 的 pip 包是纯 CPU 编译的，写 `provider=cuda` 也会回落到 CPU。真要上 GPU 得自己编译带 CUDA 的版本，和「双击即用」冲突。

CPU 单条 2~3 秒音频约 22 毫秒，比实时快 100 倍，够用。

## 适合什么素材

| 素材 | 效果 |
|---|---|
| 游戏语音包（干净、单人、无配乐） | ⭐⭐⭐⭐⭐ 非常好 |
| 有试音素材的配音工程 | ⭐⭐⭐⭐ 好 |
| 动画 / 影视（混音、多人、有 BGM） | ⭐⭐ 明显变差，建议先做人声分离 |

**声纹模型对混音很敏感。** 动画原声直接跑，准确率会掉到 70% 左右；先去背景音乐再做，会好很多。

还有一个限制来自素材本身：**如果几个角色的声线非常接近**（交互相似度 0.85 以上），CAM++ 可能分不开，这时阈值怎么调都会误判，只能靠人工校对。

## 常见问题

**Q：需要什么配置？**
4 核 / 4 GB 就能跑。4 万条在 24 线程 CPU 上约 3.5 分钟，4 核机器约 15~20 分钟。不需要显卡。

**Q：为什么「其他」里那么多？**
三个原因：① 配角/音效本来就不该归入主角 ② 阈值偏保守 ③ 你只给部分簇起了名。想看是不是漏了，把阈值调到 0.60 重新分类试试。

**Q：分类不准怎么办？**
先调阈值。调了还混入别人的声音，说明模型的区分度到顶了，只能靠人工校对或换更强的模型。

**Q：为什么同一个人被分成好几个簇？**
声纹对情绪、音高敏感。这不是 bug，反而对音色克隆有好处——你可以按情绪挑子集。

**Q：跑的时候 CPU 90 度？**
默认并发 = 线程数 ÷ 2，仍嫌热就勾「低温模式」，或把并发进程数调到 2~3。

**Q：会拿走我的音频吗？**
不会。所有处理都在本机，服务只绑定 `127.0.0.1`。

**Q：整合包为什么这么大？**
里面塞了完整 Python 运行时和依赖，约 400 MB（压缩后 167 MB）。换来的是双击即用。

## 清理中间文件

「导出」页下方有清理按钮：

| 按钮 | 释放 | 代价 |
|---|---|---|
| 删除「其他」文件夹 | 少量 | 无 |
| 清理预览和样本（保留声纹） | 几百 MB | 重新聚类要重跑 |
| 清理全部缓存（含声纹） | 几百 MB | 下次要重新提取 3.5 分钟 |

声纹缓存（`cache/embeddings.npy`）是你最值钱的文件——只要它还在，改阈值、重新分类都是秒级。
